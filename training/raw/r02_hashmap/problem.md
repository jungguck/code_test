> **P02 와 같은 문제. 단, `dict` / `set` / `Counter` 사용 금지.**

## 금지
```
dict(   set(   Counter   {   defaultdict   .count(   .sort(   sorted(   index(
```
`{` 를 통째로 막아놨다. `{}` 딕셔너리 리터럴도, `{1,2}` 집합 리터럴도 못 쓴다.
(f-string 도 못 쓰니 그냥 `print(x)` 로 출력해라)

## 입력 / 출력
P02 와 동일. N개 단어 중 최다 등장 단어, 동점이면 사전순 앞선 것.
- **N ≤ 30,000**, 단어는 영소문자 길이 1~20

## 핵심 함정 ⚠️
리스트에 단어를 넣고 `if w in words_list` 로 찾으면
찾는 데만 매번 O(길이) → 전체 **O(N × 서로다른단어수)** → 시간초과.

**해시 테이블이 왜 빠른지** 를 몸으로 아는 게 이 문제의 목적이다.

## 해시 테이블 원리

**아이디어**: 단어를 숫자로 바꿔서, 그 숫자를 **배열의 인덱스로 바로 써버린다.**
그러면 찾는 데 O(1). 리스트를 처음부터 훑을 필요가 없음.

### 1단계 — 해시 함수 (문자열 → 숫자)
문자열을 하나의 정수로 뭉갠다. 고전적인 방법이 **다항식 해시**:

```
h = 0
각 글자 c 에 대해:
    h = h * 31 + ord(c)
h = h % 버킷개수
```

`31` 은 홀수 소수라 충돌이 적게 퍼진다(자바 String.hashCode 가 쓰는 값).
`% 버킷개수` 로 배열 범위 안에 우겨넣는다.

```
"ab"  ->  h = 0*31 + 97 = 97
          h = 97*31 + 98 = 3105
          3105 % 1000 = 105        ->  105번 칸
```

### 2단계 — 충돌(collision) 처리
다른 단어인데 같은 칸이 나올 수 있다. 이걸 **충돌**이라 한다.
해결법이 **체이닝(chaining)**: 각 칸에 리스트를 하나씩 두고 거기 쭉 매단다.

```
table[105] = [ ["ab", 3], ["xk", 1] ]     <- 같은 칸에 두 단어가 매달림
               ^단어  ^횟수
```

조회할 때는 `table[105]` 안의 **몇 개만** 훑으면 된다.
버킷을 넉넉히 잡으면 한 칸에 보통 1~2개밖에 안 매달려서 사실상 O(1).

### 3단계 — 버킷 개수
데이터 개수보다 넉넉하게, **소수**로 잡는 게 관례다. (예: `50021`)
소수로 잡으면 `%` 결과가 골고루 퍼진다.

### 4단계 — 정답 고르기
테이블 전체를 한 번 순회하면서 `(횟수 더 큼)` 또는
`(횟수 같고 단어가 사전순 앞섬)` 이면 답을 갱신한다.
문자열 비교 `a < b` 는 파이썬이 알아서 사전순으로 해주니 그건 써도 된다.
