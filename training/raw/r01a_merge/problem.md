# R01a. 두 묶음 합치기 — merge 만 만든다 🔧

> **R01 의 앞 단계.** R01(병합 정렬)에서 **어려운 부분만** 떼어냈다.
> 재귀 없음. `while` 두 개와 인덱스 두 개로 끝난다.

## 왜 이 문제가 따로 있나

R01 은 새 개념이 **세 개 동시에** 나온다 — 재귀 · 분할정복 · 투 포인터.
`P01`(`nums.sort(reverse=True)` 한 줄)에서 곧바로 넘어오면 계단이 너무 크다.

그중 실제로 어려운 것은 **투 포인터로 두 묶음을 합치는 부분 하나**다.
그것만 먼저 손에 익히면 R01b 의 재귀는 네 줄이다.

## 금지
```
.sort(    sorted(    heapq
```
`heapq.merge` 가 바로 이 일을 해주므로 같이 막았다. 직접 짜야 한다.

## 입력
- 첫째 줄: `N M` — 두 묶음의 원소 개수 (0 ≤ N, M ≤ 100,000)
- 둘째 줄: N개의 정수, **이미 내림차순**으로 주어진다
- 셋째 줄: M개의 정수, **이미 내림차순**으로 주어진다
- 개수가 0이면 그 줄은 빈 줄이다

## 출력
- 두 묶음을 합쳐 **내림차순** 한 줄로, 공백으로 구분해 출력

## 예제 입력
```
2 3
5 3
4 1 1
```

## 예제 출력
```
5 4 3 1 1
```

## 핵심 — 카드 두 무더기
두 묶음이 **이미 정렬돼 있다**는 것이 전제다. 그러니 전체를 볼 필요가 없다.
책상에 카드 두 무더기를 놓고 **맨 위 두 장만 비교해서 큰 쪽을 집어낸다.** 그게 전부다.

```
L = [5, 3]   R = [4, 1, 1]
```

| i | j | left[i] | right[j] | 비교 | 가져온 값 | result |
|---|---|---|---|---|---|---|
| 0 | 0 | **5** | 4 | `5 >= 4` → 왼쪽 | 5 | `[5]` |
| 1 | 0 | 3 | **4** | `3 < 4` → 오른쪽 | 4 | `[5, 4]` |
| 1 | 1 | **3** | 1 | `3 >= 1` → 왼쪽 | 3 | `[5, 4, 3]` |
| — | — | — | — | 왼쪽이 비었음 | `[1, 1]` | `[5, 4, 3, 1, 1]` |

`i`, `j` 는 **각 무더기에서 지금 보고 있는 위치**다. 집어낸 쪽만 한 칸 전진한다.

## 함정 두 개 ⚠️

**① 남은 꼬리를 안 붙인다**

한쪽이 바닥나면 다른 쪽에 남은 것을 **통째로** 붙여야 한다. 남은 쪽은 이미 정렬돼 있고,
그 값들은 지금까지 담은 것보다 작다는 게 보장되므로 비교할 필요가 없다.

```python
merge([5, 3], [4, 1, 1])
# 꼬리 처리를 빼먹으면 -> [5, 4, 3]     (1, 1 이 사라진다)
# 제대로 하면        -> [5, 4, 3, 1, 1]
```

**② 매번 최대값을 찾는다**

```python
# ✗ 이렇게 짜면 O(N²) 이라 5번 테스트(20만 개)에서 TLE
merged = left + right
while merged:
    biggest = max(merged)      # 매번 전체를 훑는다
    result.append(biggest)
    merged.remove(biggest)
```

이미 정렬돼 있다는 **전제를 안 쓴 것**이다. 맨 앞만 보면 되는데 전체를 본다.
제대로 짜면 각 원소를 한 번씩만 지나가므로 O(N+M) 이다.
