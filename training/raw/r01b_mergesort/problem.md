## 핵심 — 실제로는 네 줄이다

`merge` 가 이미 있으면 정렬은 이렇게 끝난다.

```python
def merge_sort(arr):
    if len(arr) <= 1:               # ① 한 장이면 이미 정렬된 것
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # ② 왼쪽 절반을 정렬해서 받는다
    right = merge_sort(arr[mid:])   # ③ 오른쪽 절반도
    return merge(left, right)       # ④ 둘을 합친다
```

②③에서 **"어떻게 정렬되는지 생각하지 않는 것"** 이 요령이다.
`merge_sort` 가 정렬된 리스트를 준다고 **믿고** 받는다. 그게 재귀다.

믿어도 되는 이유는 ①이다. 계속 반으로 쪼개면 결국 한 장이 되고,
**한 장은 이미 정렬된 상태**다. 거기서부터 거꾸로 합쳐 올라온다.

```
[3, 1, 4, 1, 5]
   ↓ 쪼갠다
[3, 1]        [4, 1, 5]
   ↓ 또 쪼갠다
[3] [1]       [4]  [1, 5]
   ↑ 여기가 바닥 — 한 장이니 정렬 완료. 이제 합치며 올라온다
[3, 1]        [5, 4, 1]
   ↑
[5, 4, 3, 1, 1]
```

## 왜 굳이 직접 짜나

이 문제는 *"정렬을 직접 짜라"* 가 아니라
**"O(n²) 말고 O(n log n) 정렬을 직접 짜라"** 는 문제다.

| 방법 | 비교 횟수 (N=50,000) | 예상 시간 |
|---|---|---|
| 버블·선택 정렬 | 약 12억 5천만 번 | 파이썬으로 **약 5분 → TLE** |
| 병합 정렬 | 약 78만 번 | 0.1초 |

`N ≤ 50,000` 이라는 제약이 그 함정을 만들기 위한 값이다.
`P01` 은 `N ≤ 100,000` 인데도 괜찮았던 이유는 `sort()` 가 C 로 구현돼 있어서다.
직접 짜는 순간 알고리즘 선택이 곧 통과 여부가 된다.

## 함정 ⚠️

**① 쪼갠 절반을 안 받는다**

```python
merge_sort(arr[:mid])           # ✗ 반환값을 버렸다. 원본은 안 바뀐다
left = merge_sort(arr[:mid])    # ✓ 정렬된 새 리스트를 받아야 한다
```

`arr[:mid]` 는 **복사본**이다. 함수 안에서 뭘 해도 `arr` 은 그대로다.
그래서 반드시 `return` 값을 받아야 한다.

**② 종료조건을 빼먹는다**

`if len(arr) <= 1: return arr` 이 없으면 영원히 쪼개다가
`RecursionError: maximum recursion depth exceeded` 가 난다.

**③ 재귀 한도**

깊이는 `log₂(50000) ≈ 16` 이라 기본 한도(1000)로도 충분하다.
그래도 `sys.setrecursionlimit(10 ** 6)` 을 넣어두면 마음이 편하다.
