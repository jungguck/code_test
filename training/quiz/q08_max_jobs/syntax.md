# Q08 파이썬 문법 노트 🐍

> 공통 문법(`input()`, `map`, 출력)은 [`SYNTAX.md`](../SYNTAX.md) 참고.

## 이 문제에 나오는 문법

### 1. 리스트 컴프리헨션으로 N줄 읽기

```python
jobs = [tuple(map(int, input().split())) for _ in range(n)]
```

`for _ in range(n)` 을 오른쪽에 붙여서 **N줄을 한 방에** 리스트로 만든다.
각 줄이 `(s, e)` 튜플이 되어 `jobs = [(1,3), (3,5), ...]` 형태가 된다.

풀어 쓰면 이렇다.
```python
jobs = []
for _ in range(n):
    jobs.append(tuple(map(int, input().split())))
```

### 2. `sort(key=lambda ...)` — 정렬 기준 정하기

```python
jobs.sort(key=lambda x: (x[1], x[0]))
```

`key` 는 "각 원소를 무엇으로 보고 비교할지" 를 정한다.
`x` 는 `(s, e)` 튜플, `x[1]` 은 끝시각, `x[0]` 은 시작시각이다.

**튜플을 반환하면 앞에서부터 순서대로 비교**한다.
→ 끝시각으로 먼저 정렬, 끝시각이 같으면 시작시각으로 정렬.

```python
(3, 5)  vs  (3, 1)   ->  첫 값 같음 -> 둘째 값 5 vs 1 -> (3,1) 이 앞
```

### 3. `for s, e in jobs:` — 튜플을 바로 두 변수로

```python
for s, e in jobs:      # (1, 3) -> s=1, e=3
    if s >= end:
        ...
```

반복하면서 튜플을 **자동으로 언패킹**한다. `job[0]`, `job[1]` 로 꺼낼 필요가 없다.

### 4. 그리디의 "직전 상태" 변수

```python
end = -1               # 아직 아무것도 안 골랐을 때
for s, e in jobs:
    if s >= end:       # 직전 끝시각과 비교
        cnt += 1
        end = e         # 상태 갱신
```

그리디는 보통 **"지금까지의 마지막 상태"** 를 변수 하나로 들고 다니며 갱신한다.
여기선 `end`(마지막으로 고른 작업의 끝시각) 가 그 역할이다.

## 왜 시작시각 정렬은 틀리나

시작이 빠른 `(0, 100)` 을 먼저 고르면 뒤가 다 막힌다.
**끝이 빠른 걸 골라야 뒤에 남는 시간이 최대**가 된다 — 이게 이 문제의 정당성(증명)이다.
