## 이 문제에 나오는 문법

### 1. 답을 이분탐색 (파라메트릭 서치)

배열에서 값을 찾는 이분탐색이 아니라, **답 자체를 이분탐색**한다.

```python
lo, hi = 0, max(a)          # 높이 H의 가능한 범위
ans = 0
while lo <= hi:
    mid = (lo + hi) // 2     # 후보 높이
    if 조건(mid):            # 이 높이로 충분한가?
        ans = mid            # 되면 기록하고
        lo = mid + 1         # 더 높여본다
    else:
        hi = mid - 1         # 안 되면 낮춘다
print(ans)
```

이 틀은 "**조건을 만족하는 최대/최소 값**" 유형에서 그대로 재사용된다.
외워두면 나무 자르기·랜선 자르기·공유기 설치 등이 전부 같은 코드가 된다.

### 2. `//` 정수 나눗셈으로 중간값

```python
mid = (lo + hi) // 2
```

`/` 는 실수(`3.5`)를 주지만 `//` 는 **몫만**(`3`) 준다. 인덱스·높이 같은
정수 후보엔 항상 `//` 를 쓴다.

### 3. 제너레이터로 조건 계산

```python
total = sum(x - mid for x in a if x > mid)
```

`[ ... ]` 대신 `( ... )` 없이 `sum(...)` 안에 바로 쓰면 **제너레이터**다.
리스트를 새로 만들지 않고 **하나씩 더하며 흘려보내서** 메모리를 아낀다.
- `for x in a` : 각 통나무를
- `if x > mid` : H보다 긴 것만 골라
- `x - mid` : 넘는 만큼을 더한다

### 4. 왜 이분탐색이 되나 — 단조성

```
H가 커질수록  ->  얻는 양은 작아진다  (또는 그대로)
```

"H를 키우면 양이 준다" 는 **한 방향으로만 변하는(단조) 성질**이 있어서,
어느 지점을 기준으로 "OK / 부족" 이 딱 갈린다. 이 경계를 이분탐색으로 찾는 것이다.
단조성이 없으면 이분탐색을 쓸 수 없다 — 이게 적용 가능 여부의 판단 기준이다.

## 함정

- `while lo < hi` 로 쓰면 마지막 한 칸을 놓치기 쉽다. **`lo <= hi`** 로 두고
  `ans` 에 따로 기록하는 방식이 실수가 적다.
- `hi` 를 `max(a)` 로 잡아야 한다. `sum(a)` 같은 큰 값으로 잡으면 쓸데없이 반복이 는다.
