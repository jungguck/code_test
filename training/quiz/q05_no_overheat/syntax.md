# Q05 파이썬 문법 노트 🐍

> 공통 문법은 [`SYNTAX.md`](../SYNTAX.md) 참고.

## 이 문제에 나오는 문법

### 1. ⭐ 다중 할당 — 오른쪽이 **먼저 전부** 평가된다

```python
prev2, prev1 = prev1, cur
```

이 한 줄이 이 문제의 핵심 문법이다. 파이썬은 `=` 오른쪽을 **전부 먼저 계산해서
임시 묶음(튜플)으로 만든 뒤**, 그걸 왼쪽에 나눠 담는다.

```python
a, b = 1, 2
a, b = b, a        # 오른쪽 (2, 1) 을 먼저 만든 뒤 대입 → a=2, b=1
```

그래서 **임시 변수 없이 스왑**이 된다. 다른 언어에서 `tmp = a; a = b; b = tmp` 라고
쓰던 걸 한 줄로 끝낸다.

한 줄씩 나눠 쓰면 **틀린다**:
```python
prev2 = prev1      # ✗ prev2 가 먼저 덮어써지고
prev1 = cur        #    그 다음 prev1 이 바뀐다 → 순서에 따라 값이 꼬인다
```
이 문제는 마침 위 순서가 우연히 맞지만, 반대로 쓰면 바로 틀린다. **다중 할당이 안전하다.**

### 2. 슬라이딩 변수로 DP 배열 없애기

```python
prev2 = 0          # dp[i-2]
prev1 = 0          # dp[i-1]
for ...:
    cur = ...      # dp[i]
    prev2, prev1 = prev1, cur
```

점화식이 **바로 앞 두 개만** 참조하면 배열 전체를 들고 있을 필요가 없다.
`dp = [0] * n` 으로 짜도 정답이지만, 이렇게 하면 메모리가 O(N) → **O(1)** 이 된다.

영어권 인터뷰의 단골 팔로업 "Can you do it in O(1) space?" 의 답이 정확히 이 패턴이다.
피보나치, 계단 오르기, House Robber 전부 같은 방식으로 줄일 수 있다.

**주의**: 나중에 "어떤 날을 골랐는지" 경로를 복원해야 하면 배열이 필요하다.
값만 필요할 때 쓰는 최적화다.

### 3. 조건부 표현식으로 max 대신 쓰기

```python
cur = prev1 if prev1 > prev2 + x else prev2 + x
```
`max(prev1, prev2 + x)` 와 같은 뜻이다. 10만 번 반복이라 함수 호출을 아낀 것.

읽기 쉬운 쪽은 확실히 `max` 다. 실제 코테에서는 이렇게 써도 대부분 통과한다.
```python
cur = max(prev1, prev2 + x)
```

### 4. `range(1, 1 + n)` — 시작과 끝 지정

```python
for i in range(1, 1 + n):
    x = int(data[i])
```

`range(시작, 끝)` 은 **시작 포함, 끝 미포함**. `data[0]` 은 N이므로 1번부터 n개를 읽는다.

```python
range(5)          # 0 1 2 3 4        (0부터)
range(2, 5)       # 2 3 4            (2부터 4까지)
range(5, 0, -1)   # 5 4 3 2 1        (거꾸로, 세 번째가 증가폭)
```

### 5. 인덱스가 1부터인 척하기

문제 지문은 "i일째"라고 1부터 세는데 파이썬 리스트는 0부터다. 두 가지 대처법:

```python
# ① 그냥 0부터 쓰고 머릿속으로 변환 (이 풀이의 방식)
for i in range(n):  ...  a[i]      # i=0 이 1일째

# ② 앞에 더미를 하나 끼워서 1부터 맞추기
a = [0] + 실제값들                  # a[1] 이 1일째 → 지문과 인덱스가 일치
dp = [0] * (n + 1)
```

DP 문제에서는 **②가 실수를 확 줄인다.** `dp[i-2]` 를 쓸 때 `i=1` 에서 `dp[-1]` 이
되어버리는 사고를 막아준다 (파이썬의 `-1` 은 에러가 아니라 **맨 뒤 원소**라서 조용히 틀린다).

```python
dp = [0, 0, 0]
dp[-1]        # ✗ 에러가 아니라 맨 뒤 값(0)이 나온다 → 버그를 못 찾는다
```
