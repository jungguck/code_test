## 이 문제에 나오는 문법

### 1. 리스트 슬라이싱 `data[2:2 + n]`

```python
data = [b'5', b'50', b'-30', b'-40', b'60']
ds = data[2:2 + 3]      # → [b'-30', b'-40', b'60']
```

`a[시작:끝]` 은 **시작은 포함, 끝은 미포함**이다. 이게 슬라이싱의 전부.

```python
a = [0, 1, 2, 3, 4]
a[1:3]     # [1, 2]     ← 3번은 안 들어온다
a[2:]      # [2, 3, 4]  ← 끝을 비우면 "끝까지"
a[:2]      # [0, 1]     ← 시작을 비우면 "처음부터"
```

그래서 "2번째부터 n개" 는 `data[2 : 2+n]` 이라고 쓴다.
범위를 넘겨도 에러가 안 나고 있는 만큼만 준다(`a[1:100]` → `[1,2,3,4]`).
**인덱스 접근(`a[100]`)은 IndexError 인데 슬라이싱은 안 난다**는 게 헷갈리는 지점.

### 2. `+=` (복합 대입 연산자)

```python
b += int(x)        # b = b + int(x) 와 같다
empty += 1         # empty = empty + 1
```
`-=`, `*=`, `//=` 도 같은 식으로 쓴다. 코드가 짧아지고 변수 이름을 두 번 안 써서 오타가 준다.

### 3. `if / elif` 로 값 자르기 (clamp)

```python
if b < 0:
    b = 0
elif b > 100:
    b = 100
```

`elif` 는 **앞의 if 가 거짓일 때만** 검사한다. 여기선 `b`가 0보다 작으면서
동시에 100보다 클 수는 없으니 `elif` 가 맞다. (`if` 두 개로 써도 결과는 같지만 한 번 더 비교한다)

한 줄로 줄이면 이렇게도 된다 — 실무/코테 양쪽에서 자주 보는 관용구:
```python
b = max(0, min(100, b))
```
안쪽 `min(100, b)` 가 위를 자르고, 바깥 `max(0, ...)` 가 아래를 자른다.

### 4. `print(a, b)` — 콤마로 여러 값 출력

```python
print(b, empty)     # "20 2"
```
`print` 는 인자 사이에 **자동으로 공백 하나**를 넣는다. 그래서 `print(str(b) + " " + str(empty))`
처럼 쓸 필요가 없다.

구분자를 바꾸고 싶으면:
```python
print(a, b, sep=',')     # "20,2"
print(a, end='')         # 줄바꿈 없이
```

### 5. 반복문 안에서 `int()` 변환

```python
for x in ds:
    b += int(x)
```

`data` 의 원소는 **bytes**(`b'-30'`)지 숫자가 아니다. `int()` 로 바꿔야 계산이 된다.

```python
b'-30' + 5        # ✗ TypeError
int(b'-30') + 5   # ✓ -25
```

미리 `ds = list(map(int, data[2:2+n]))` 로 통째로 바꿔놓고 쓰는 방법도 있다.
둘 다 맞고, 원소를 한 번씩만 쓸 거면 루프 안에서 변환하는 쪽이 메모리를 덜 쓴다.

## 이 문제에서 실수하기 쉬운 곳

```python
b += int(x)
if b == 0:          # ✗ 자르기 전에 확인 → -40 일 때 0이 아니라서 못 센다
    empty += 1
if b < 0: b = 0
```
**자른 다음에** 0인지 봐야 한다. 순서가 곧 정답이다.
