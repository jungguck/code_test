## 문제
1부터 N까지의 자연수를 **이진 탐색 트리**에 저장한다.
트리는 **완전 이진 트리**이고, 노드 번호는 루트가 1번, 위에서 아래로·왼쪽에서 오른쪽으로 1, 2, 3 … 순서로 붙는다.
이진 탐색 트리이므로 모든 노드는 **왼쪽 자식 < 나 < 오른쪽 자식** 을 만족한다.
루트(1번 노드)에 저장된 값과, **N/2번 노드**에 저장된 값을 출력한다.

## 입력
- 첫째 줄: 테스트 케이스의 개수 T
- 다음 T줄: 각 줄에 N (1 ≤ N ≤ 1000)

## 출력
- 각 줄은 `#t` 로 시작하고, 공백 한 칸 뒤에 루트의 값, 공백 한 칸 뒤에 N/2번 노드의 값을 출력한다

## 예제
```
입력      출력
3         #1 4 6
6         #2 5 2
8         #3 8 14
15
```
N=6 이면 트리는 아래처럼 채워진다. 루트 = 4, 6//2 = 3번 노드 = 6.
```
노드 번호              저장된 값
      1                    4
    /   \                /   \
   2     3              2     6
  / \   /              / \   /
 4   5 6              1   3 5
```

## 풀이 아이디어
> **제목에 속지 말 것.** 여기서 "이진탐색"은 업다운 게임처럼 반씩 줄여 찾는 **이진 탐색 알고리즘이 아니다.**
> 하는 일은 **나무 모양 자리에 1, 2, 3 … 을 규칙대로 채우기** 다.

**먼저 "번호" 와 "값" 을 구분한다.** 이게 제일 헷갈린다.
- **번호(번호표)** = 자리 이름. 위→아래, 왼→오른쪽으로 1, 2, 3 … 이미 붙어 있다. 우리가 정하는 게 아니다.
- **값** = 그 자리에 **써넣을 숫자**. 이걸 구하는 게 문제다.

**문제를 두 개로 쪼갠다.**

**① 트리를 리스트 하나로 표현한다.**
노드 번호를 리스트 인덱스로 쓰면, 자식을 곱셈으로 찾을 수 있다.
```
i 번 노드의  왼쪽 자식 = i * 2
            오른쪽 자식 = i * 2 + 1
            부모       = i // 2
```
N=6 에서 1번의 자식은 2·3, 2번의 자식은 4·5, 3번의 자식은 6·7 — 그런데 7 > N 이므로 **7번은 없다.**
→ **번호가 N 보다 크면 "거기엔 노드가 없다"** 는 뜻이다. 이게 코드의 `curr <= N` 검사다.

**② 어떤 순서로 1, 2, 3 … 을 넣나 → 중위 순회.**
"왼쪽 < 나 < 오른쪽" 이니까 **가장 작은 수(1)는 제일 왼쪽 아래**에 들어간다.
그 다음 작은 수는 그 부모, 그 다음은 부모의 오른쪽 …
이 순서 **"왼쪽 먼저 다 → 나 → 오른쪽"** 을 **중위 순회**라고 한다.
중위 순회로 노드를 방문하면서 1, 2, 3 … 을 차례로 적어 넣으면 끝이다.

**③ 스택은 "되돌아올 곳 메모장".**
왼쪽으로 쭉 내려갈 때, 지나온 노드를 아직 못 채웠다(왼쪽을 먼저 채워야 하니까).
그래서 **나중에 돌아와서 채우려고** 스택에 적어 둔다.
막히면(더 내려갈 곳이 없으면) **가장 최근에 적은 노드**로 돌아가서 숫자를 쓰고, 그 오른쪽으로 간다.

반복 한 번에 하는 일은 세 가지뿐이다.
1. **왼쪽으로 끝까지 내려가며** 지나는 노드를 스택에 쌓는다
2. 막히면 스택 **맨 위**를 꺼내서 다음 숫자를 쓴다
3. 꺼낸 노드의 **오른쪽 자식**으로 옮겨 간다 (없으면 다음 회차에 바로 2번으로)

스택도 비고, 갈 곳도 없으면 끝.

## 코드 따라가기
```python
    N = int(input())
    tree = [0] * (N + 1)
    current_val = 1
```
`tree[i]` = i번 노드에 들어갈 값. 노드 번호가 1부터라 **N+1칸**을 만들고 0번 칸은 버린다.
`current_val` = 다음에 써 넣을 숫자. 1부터 시작한다. (`val` = value, 값)

```python
    stack = []
    curr = 1
```
`curr` = 지금 서 있는 노드 **번호**. 루트(1번)에서 출발한다. (`curr` = current, 지금)

**`curr` 와 `current_val` 은 이름만 비슷하고 완전히 다르다.**

| 변수 | 뜻 | 비유 | 움직임 |
|---|---|---|---|
| `curr` | 지금 서 있는 **자리 번호** | 내 발 위치 | 1→2→4→… 나무 위를 이리저리 돌아다닌다 |
| `current_val` | 다음에 쓸 **값** | 손에 든 펜의 숫자 | 1, 2, 3 … **딱 1씩만** 올라간다 |

`tree[curr] = current_val` = **"지금 서 있는 자리에, 지금 쓸 숫자를 적어라."**

```python
    while curr <= N or stack:
```
**"아직 갈 노드가 있거나, 돌아갈 곳이 메모돼 있으면"** 계속한다.
둘 다 없으면(= 갈 곳도 돌아갈 곳도 없음) 모든 노드를 다 채운 것이다.

```python
        while curr <= N:
            stack.append(curr)
            curr *= 2
```
**왼쪽으로 쭉 내려가기.** 지금 노드를 메모장(스택)에 적고, 왼쪽 자식(`* 2`)으로 간다.
`curr` 가 N 을 넘는 순간 = 노드가 없는 곳에 도착 → 멈춘다.

**`curr *= 2` 는 위가 아니라 아래로 간다.** 숫자가 커져서 올라가는 것 같지만, 이 나무는 **뿌리가 맨 위에 있는 거꾸로 선 나무**다.
번호가 커질수록 아래다.

| 움직임 | 계산 | 2번에서 출발하면 |
|---|---|---|
| 왼쪽 **아래** | `curr * 2` | 4번 |
| 오른쪽 **아래** | `curr * 2 + 1` | 5번 |
| **위** | `curr // 2` | 1번 |

(이 코드는 `// 2` 를 안 쓴다. 위로 갈 때는 계산 대신 **스택에 적어 둔 번호를 꺼낸다.**)

**바깥 `while` 1회차 안에서 안쪽 `while` 은 여러 번 돈다.** 조건이 틀릴 때까지 계속 도는 반복문이라서다.
N=6 첫 회차, curr=1 에서 시작:

| 안쪽 while | `curr <= 6`? | `append` 후 stack | `curr *= 2` |
|:-:|---|---|:-:|
| 1번째 | 1 ≤ 6 → 들어감 | [1] | 2 |
| 2번째 | 2 ≤ 6 → 들어감 | [1, 2] | 4 |
| 3번째 | 4 ≤ 6 → 들어감 | [1, 2, 4] | 8 |
| 4번째 | 8 ≤ 6? **아니다** → 멈춤 | | |

**왜 한꺼번에 적나?** 1 을 쓸 곳은 맨 왼쪽 끝인데, 끝이 어딘지 내려가 봐야 안다.
지나온 1번·2번은 **왼쪽을 먼저 채워야** 쓸 수 있으니, 나중에 돌아올 곳으로 메모해 두는 것이다.

```python
        curr = stack.pop()
        tree[curr] = current_val
        current_val += 1
```
막혔으니 **가장 최근 메모(스택 맨 위)** 로 돌아간다. `pop()` 은 맨 뒤(=맨 위)를 꺼낸다.
그 노드의 왼쪽은 이미 다 채웠거나 원래 없다 → 이제 **이 노드 차례**. 숫자를 쓰고 1 올린다.

**`pop()` 은 1 부터가 아니라 맨 뒤부터 꺼낸다.** 접시 쌓기와 같다 — 마지막에 올린 접시를 먼저 집는다.
```python
stack = [1, 2, 4]
stack.pop()   # 4 가 나옴 → [1, 2]
stack.pop()   # 2 가 나옴 → [1]
stack.pop()   # 1 이 나옴 → []
```
1 → 2 → 4 로 **내려왔으니** 돌아갈 땐 4 → 2 → 1 로 **한 칸씩 올라가야** 한다. 뒤부터 꺼내면 딱 그 순서다.
(`pop(0)` 은 맨 앞부터 꺼낸다 = 줄 서기. BFS 에서 쓰는 쪽이다. 여기선 괄호를 비운 `pop()`.)

```python
        curr = curr * 2 + 1
```
이제 **오른쪽 자식**으로 간다.
오른쪽 자식이 없으면(`> N`) 다음 회차에서 안쪽 `while` 이 한 번도 안 돌고 바로 `pop()` → 한 칸 위로 돌아간다.

```python
    print(f"#{test_case} {tree[1]} {tree[N // 2]}")
```
`tree[1]` = 루트의 값, `tree[N // 2]` = N/2번 노드의 값. (`//` 는 몫만 남기는 나눗셈)

**왜 `#{test_case}` 를 붙이나?** 문제가 출력을 "`#t` 로 시작하라" 고 정했기 때문이다. SWEA 는 거의 다 이렇다.
`test_case` 는 맨 위 `for test_case in range(1, T + 1):` 에서 만든 변수라 1, 2, 3 … 으로 바뀐다.
`#` 은 그냥 글자라 그대로 찍히고, `{ }` 안만 값으로 바뀐다 → `#1 4 6`.
출력 설명에 `#t` 가 없는 문제(예: 산불 수열)는 붙이지 않는다. **출력 설명을 보고 정한다.**

### N=6 을 표로 따라가기
| 회차 | 왼쪽으로 내려가며 쌓음 | 멈춘 곳 | pop → 값 쓰기 | 스택 (쓴 뒤) | 다음 curr (오른쪽) |
|:-:|---|:-:|:-:|---|:-:|
| 1 | 1, 2, 4 | 8 (없음) | **4번 ← 1** | [1, 2] | 9 (없음) |
| 2 | — (9는 없음) | 9 | **2번 ← 2** | [1] | 5 |
| 3 | 5 | 10 (없음) | **5번 ← 3** | [1] | 11 (없음) |
| 4 | — | 11 | **1번 ← 4** | [] | 3 |
| 5 | 3, 6 | 12 (없음) | **6번 ← 5** | [3] | 13 (없음) |
| 6 | — | 13 | **3번 ← 6** | [] | 7 (없음) |
| 끝 | curr=7 > 6 이고 스택도 빔 → 종료 | | | | |

결과 `tree = [0, 4, 2, 6, 1, 3, 5]` → 루트 `tree[1] = 4`, `tree[3] = 6` → `#1 4 6`.

값을 쓴 순서가 **4번 → 2번 → 5번 → 1번 → 6번 → 3번**. 그림에서 보면 정확히 **왼쪽 아래부터 오른쪽으로** 훑은 순서다.
```
      1(4)
    /     \
  2(2)    3(6)
  /  \    /
4(1) 5(3) 6(5)      ← 괄호 안 = 들어간 값. 왼쪽부터 읽으면 1 2 3 4 5 6
```

### N=7 도 따라가기 (꽉 찬 나무)
번호표는 1~7, **8번 이상은 없는 자리**다.

| 회차 | ① 내려가며 적기 | ② 꺼내서 쓰기 (`curr` ← `current_val`) | ③ 오른쪽으로 | 끝난 뒤 stack |
|:-:|---|:-:|---|---|
| 1 | 1, 2, 4 (8 없음) | **4번 ← 1** | 9 (없음) | [1, 2] |
| 2 | — (9 없음) | **2번 ← 2** | 5 | [1] |
| 3 | 5 (10 없음) | **5번 ← 3** | 11 (없음) | [1] |
| 4 | — (11 없음) | **1번 ← 4** | 3 | [] |
| 5 | 3, 6 (12 없음) | **6번 ← 5** | 13 (없음) | [3] |
| 6 | — (13 없음) | **3번 ← 6** | 7 | [] |
| 7 | 7 (14 없음) | **7번 ← 7** | 15 (없음) | [] |
| 끝 | curr=15 도 없고 stack 도 빔 → 종료 | | | |

"— (없음)" = 번호가 N 보다 커서 안쪽 `while` 에 **아예 못 들어간다** → 바로 `pop()` = 한 칸 위로.
```
         1(4)
       /      \
    2(2)      3(6)
    /  \      /  \
 4(1) 5(3) 6(5) 7(7)     ← 옆으로 눌러서 왼쪽부터 읽으면 1 2 3 4 5 6 7
```
`tree[1] = 4`, `tree[7 // 2] = tree[3] = 6` → `#1 4 6`.
꽉 찬 나무는 좌우가 똑같이 생겨서 루트에 **딱 가운데 수(4)** 가 들어간다.

### 헷갈렸던 것 모음
| 헷갈린 것 | 답 |
|---|---|
| 이진탐색 = 반씩 줄여 찾기? | 아니다. **이진 탐색 트리에 1~N 채우기** 문제다 |
| `curr` vs `current_val` | `curr` = **자리 번호**(발), `current_val` = **쓸 값**(펜) |
| `curr *= 2` 는 위로? | **아래로.** 뿌리가 맨 위라 번호가 커질수록 아래다 |
| 1회차인데 왜 1, 2, 4 를 다 적나? | 1회차 안에서 **안쪽 while 이 3번** 돈다 |
| `pop()` 은 1 부터 꺼내나? | **맨 뒤부터.** [1, 2, 4] 면 4 가 먼저 |
| `#{test_case}` 는 왜? | 문제가 `#t` 로 시작하라고 해서. `test_case` = 1, 2, 3 … |
| 결국 값은 어떤 순서로 들어가나? | 나무를 옆으로 눌러 **왼쪽부터 읽으면 1, 2, 3 …** |

## 외울 것
> **완전 이진 트리 = 리스트 하나. `i` 의 왼쪽 `i*2`, 오른쪽 `i*2+1`, 부모 `i//2`, 번호가 N 넘으면 없는 노드.**
> **이진 탐색 트리에 1~N 채우기 = 중위 순회 순서대로 1, 2, 3 … 쓰기.**
> **반복문 중위 순회: 왼쪽 끝까지 `append` → 막히면 `pop` 해서 값 쓰기 → `*2+1` 로 오른쪽. `while curr <= N or stack:`**
> **`curr` = 자리(발), `current_val` = 값(펜). `*2` 는 아래로, `pop()` 은 맨 뒤부터 = 한 칸 위로.**
