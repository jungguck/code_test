# QWEN에게 줄 프롬프트 — 카드 만들기

아래 `=====` 사이를 **그대로 복사해서** QWEN에게 붙여넣는다.
`{번호}` `{제목}` `{난이도}` `{분류}` `{코드}` 다섯 군데만 바꿔 넣으면 된다.

한 번에 **한 장씩** 시킨다. 74장을 한꺼번에 시키면 품질이 무너진다.

=====
너는 코딩테스트 공부용 "답지 카드"를 만드는 역할이다.

읽는 사람은 **파이썬 문법도 아직 헷갈리는 초보**다.
이 사람은 문제를 스스로 풀지 못하고, **정답 코드를 읽고 패턴을 외우려고** 한다.
그러니 "이렇게 푼다" 가 아니라 **"왜 이렇게 푸는지, 이 줄이 무슨 뜻인지"** 를 써야 한다.

## 주어지는 것

- 문제 번호: {번호}
- 문제 제목: {제목}
- 난이도: {난이도}
- 분류: {분류}          (01_graph = 그래프탐색·완전탐색 / 02_ds = 자료구조 / 03_dp = DP)
- 정답 코드:
```python
{코드}
```

## 절대 규칙

1. **코드를 고치지 마라.** 코드는 이미 검증된 정답이다. 너는 설명만 붙인다.
2. **문제 지문을 지어내지 마라.** 지문은 **코드에서 읽어낼 수 있는 것**으로 복원한다.
   - 입력 형식은 코드의 `input()` 호출 순서를 **그대로** 따른다
   - 출력 형식은 코드의 `print()` 를 **그대로** 따른다
   - 이 규칙을 지키면 지문과 정답이 어긋날 수가 없다
3. 코드만 봐서는 알 수 없는 것(N의 최대값 같은 제약 조건)은 **추측하지 말고** 이렇게 표시한다.
   ```
   <!-- 확인필요: N의 최대 범위를 코드만으로는 알 수 없음 -->
   ```
4. **코드가 틀린 것 같으면** `## ⚠️ 이 코드의 버그` 항목을 추가하고,
   **틀리는 입력 예시와 올바른 답**을 구체적으로 적어라. 확신 없으면 "확인필요" 로 남겨라.
5. 파이썬 특유의 문법이 코드에 나오면 **반드시 풀어서 설명**한다.
   `for ... else` / 리스트 컴프리헨션 / 삼항식 / `*` 언패킹 / 슬라이싱 / `enumerate` / `zip` 등.
   초보는 이것 때문에 코드를 못 읽는다.
6. 전부 **한국어**로 쓴다.
7. 아래 **일곱 개 항목을 빠짐없이** 넣는다. 항목 제목을 바꾸지 마라.

```markdown

no: {번호}
title: {제목}
tier: {난이도}
cat: {분류}
topic: (한 줄로 쓰는 세부 유형. 예: "DP · 1차원 점화식", "BFS · 격자 최단거리")
---

(무엇을 구하는 문제인지. 규칙이 여러 개면 번호를 매겨 나열한다)

## 입력
(코드의 input() 순서 그대로. 첫째 줄에 무엇, 다음 줄에 무엇)

## 출력
(코드의 print() 그대로)

## 예제
```
입력          출력
...           ...
```
(왜 그 답이 나오는지 한두 줄 덧붙인다)

## 풀이 아이디어
(가장 중요한 항목이다. 이 문제를 푸는 **핵심 질문**이 무엇인지부터 쓴다.

 그래프면 무엇을 정점으로 보고 무엇을 간선으로 보는지 밝힌다.
 그림이나 표를 ``` 블록으로 그려서 보여주면 훨씬 좋다)

 "왜 이 줄이 필요한가", "이걸 빼면 어떻게 틀리는가" 를 같이 적으면 좋다)

## 참고할 완성본

`study/cards/03_dp/2579.md` 와 `study/cards/02_ds/9012.md` 가 이미 완성된 카드다.
**분량과 깊이를 이 두 장에 맞춰라.** 더 짧으면 쓸모가 없고, 겉핥기면 만드는 의미가 없다.

## 만든 뒤에 할 일

1. 결과를 `study/cards/{분류}/{번호}.md` 로 저장한다
2. 검사한다
   ```
   python study/cards/build.py
   ```
   - `[X]` 가 뜨면 빠진 항목이 있다는 뜻이다. 사유를 보고 고친다
   - 통과하면 `cards.json` 이 자동으로 갱신된다
3. 아직 안 만든 목록 확인
   ```
   python study/cards/build.py --todo
   ```

## 품질이 떨어지면

QWEN이 대충 쓰면 (풀이 아이디어가 두세 줄로 끝나거나, 코드를 그냥 한국어로 옮기기만 하면)
프롬프트에 이 문장을 덧붙인다.

> 2579.md 를 먼저 읽고, 그 분량과 깊이에 맞춰라. 코드를 한국어로 번역하지 말고,
> **왜 그렇게 짰는지**와 **초보가 어디서 틀리는지**를 써라.
