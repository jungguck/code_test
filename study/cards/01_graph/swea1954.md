## 문제
N × N 칸에 1부터 N² 까지 숫자를 **달팽이 모양**(바깥에서 안으로, 시계 방향)으로 채워서 출력하라.
1. (0, 0) 에서 오른쪽으로 출발한다
2. 벽에 닿거나 이미 숫자가 있는 칸을 만나면 **시계 방향으로 90° 꺾는다** (우 → 하 → 좌 → 상 → 우 …)

## 입력
- 첫째 줄: 테스트 케이스의 개수 T
- 다음 T줄: 각 줄에 N (1 ≤ N ≤ 10)

## 출력
- 케이스마다 첫 줄에 `#t`
- 다음 N줄에 한 줄씩, 숫자를 빈칸으로 띄워 출력

## 예제
```
입력   출력
2      #1
3      1 2 3
4      8 9 4
       7 6 5
       #2
       1 2 3 4
       12 13 14 5
       11 16 15 6
       10 9 8 7
```
N=3: 1→2→3 오른쪽, 벽 → 4→5 아래, 벽 → 6→7 왼쪽, 벽 → 8 위, 1이 있음 → 9 오른쪽.

## 풀이 아이디어
**핵심 질문: "다음 칸으로 가도 되나? 안 되면 어느 쪽으로 꺾나?"**

BFS 문제는 아니지만, BFS/DFS 격자 문제에서 **매번 쓰는 도구 두 개**를 그대로 쓴다.
그래서 그래프 탐색 묶음에 넣었다.

**① 방향 배열 `dr`, `dc`**
"오른쪽으로 한 칸" = 행은 그대로, 열 +1. 이걸 네 방향 다 표로 만들어 둔다.
```
direction   0(우)  1(하)  2(좌)  3(상)
dr          0      1      0     -1     ← 행 변화
dc          1      0     -1      0     ← 열 변화
```
그러면 "지금 방향으로 한 칸" 은 언제나 `r + dr[direction], c + dc[direction]` 한 줄로 끝난다.
순서를 **우·하·좌·상(시계 방향)** 으로 놓은 게 포인트다 → `direction + 1` 이 곧 "오른쪽으로 꺾기".

**② 갈 수 있는 칸인지 검사** (BFS 에서도 똑같이 쓴다)
```
0 <= nr < N and 0 <= nc < N   → 격자 안인가?
arr[nr][nc] == 0              → 아직 안 채운 칸인가? (BFS 의 visited 역할)
```
둘 중 하나라도 걸리면 방향을 꺾는다.

**따라가기 — N = 3**

| num | 칸 (r,c) | 미리 본 다음 칸 | 막혔나? | 실제 다음 칸 |
|:-:|:-:|:-:|---|:-:|
| 1 | (0,0) | (0,1) | 아니오 | (0,1) |
| 3 | (0,2) | (0,3) | 범위 밖 → 하로 꺾음 | (1,2) |
| 5 | (2,2) | (3,2) | 범위 밖 → 좌로 꺾음 | (2,1) |
| 7 | (2,0) | (2,-1) | 범위 밖 → 상으로 꺾음 | (1,0) |
| 8 | (1,0) | (0,0) | 1 이 있음 → 우로 꺾음 | (1,1) |
| 9 | (1,1) | — | 마지막 숫자라 끝 | — |

## 코드 따라가기
```python
dr = [0, 1, 0, -1]
dc = [1, 0, -1, 0]
```
방향 배열. 케이스마다 안 바뀌니까 반복문 **밖**에 한 번만 만든다.

```python
    arr = [[0] * N for _ in range(N)]
```
0으로 찬 N×N 격자. `[... for _ in range(N)]` 은 아래를 한 줄로 쓴 것이다.
```
arr = []
for _ in range(N):
    arr.append([0] * N)
```
`[[0] * N] * N` 으로 쓰면 **안 된다.** 같은 줄 하나를 N번 가리키게 돼서
`arr[0][0] = 1` 하면 모든 줄의 0번 칸이 1이 된다.

```python
    r, c = 0, 0
    direction = 0
```
현재 위치 (0, 0), 현재 방향 0번(오른쪽).

```python
    for num in range(1, N * N + 1):
        arr[r][c] = num
```
숫자는 정확히 N² 개 → 1 부터 N² 까지 돌면서, 지금 칸에 숫자를 적는다.
`range(1, N*N + 1)` 은 끝 값을 **포함하지 않으므로** `+1` 을 붙인다.

```python
        nr = r + dr[direction]
        nc = c + dc[direction]
```
움직이기 **전에** 다음 칸을 미리 계산해 본다. (`n` = next)

```python
        if not (0 <= nr < N and 0 <= nc < N) or arr[nr][nc] != 0:
```
"범위 밖이거나, 이미 채운 칸이면" 이라는 뜻이다.
- `0 <= nr < N` : 파이썬은 비교를 이어 쓸 수 있다. `0 <= nr and nr < N` 과 같다.
- **순서가 중요하다.** `or` 는 왼쪽이 참이면 오른쪽을 **아예 안 본다.**
  범위 밖이면 거기서 멈추니까 `arr[nr][nc]` 를 안 건드린다 → `IndexError` 가 안 난다.
  두 조건을 거꾸로 쓰면 `arr[0][3]` 을 보려다 터진다.
  (`nc = -1` 은 터지지는 않지만 **맨 끝 칸**을 봐 버린다. 그래서 범위 검사가 먼저 와야 한다.)

```python
            direction = (direction + 1) % 4
            nr = r + dr[direction]
            nc = c + dc[direction]
```
시계 방향으로 꺾고, 새 방향으로 다음 칸을 다시 계산한다.
`% 4` 는 4로 나눈 나머지 → `3 + 1 = 4` 가 `0` 으로 돌아온다. (상 → 우)

```python
        r, c = nr, nc
```
실제로 이동한다. 마지막 숫자를 적은 뒤에도 한 번 계산·이동하지만,
그 칸에 숫자를 적기 전에 반복이 끝나므로 상관없다.

```python
    print(f"#{test_case}")
    for row in arr:
        print(*row)
```
`*row` — 리스트를 풀어서 따로따로 넘긴다. `print(1, 2, 3)` 과 같아서 빈칸으로 이어 찍힌다.
`print(row)` 로 쓰면 `[1, 2, 3]` 처럼 대괄호까지 나와서 틀린다.

## 외울 것
> **격자 이동 = `dr`, `dc` 방향 배열 + `nr, nc` 를 미리 계산 + "범위 안 and 아직 안 간 칸" 검사.**
> **범위 검사를 `or`/`and` 의 앞에 둬야 `arr[nr][nc]` 에서 안 터진다.**
> **방향 순서를 시계 방향으로 놓으면 꺾기는 `(direction + 1) % 4` 한 줄.**
