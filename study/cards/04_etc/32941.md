## 문제
건우가 교실을 `X`교시에 예약해버렸다. 조원 `N`명이 각자 참석 가능한 교시 목록을 알려줬다.
`X`교시에 **모든 조원이 참석할 수 있으면** `YES`, 한 명이라도 못 오면 `NO` 를 출력하라.

## 입력
- 첫째 줄: 교시의 총 개수 `T` 와 예약한 교시 `X` (공백으로 구분, 1 ≤ T ≤ 1,000 / 1 ≤ X ≤ T)
- 둘째 줄: 조원의 수 `N` (1 ≤ N ≤ 10)
- 그다음 **조원 1명당 두 줄씩**, N명분:
  - 첫 줄: 그 조원이 참석 가능한 교시의 개수 `K` (1 ≤ K ≤ T)
  - 둘째 줄: 참석 가능한 교시 `K`개 (공백 구분, 오름차순)

⚠ **첫째 줄에 오는 건 `T` 와 `X` 두 개다.** `N` 은 둘째 줄에 따로 온다. 그리고 조원 정보는 "N줄"이 아니라 **2N줄**이다 — 개수 줄(`K`)이 앞에 하나씩 붙는다. 이 구조를 착각하면 첫 줄부터 터진다.

## 출력
- `YES` 또는 `NO` 한 줄

## 예제
```
입력                   출력
7 3                    NO
4
1
4
6
1 2 4 5 6 7
3
1 3 4
2
4 7
```
`T=7`, `X=3`, `N=4`. 1번 조원은 `[4]` 만 가능해서 3교시에 못 온다 → 그 순간 `NO` 가 확정된다.

3번 조원은 `[1,3,4]` 로 3교시가 가능하지만, **이미 안 되는 사람이 있으므로 결과는 안 뒤집힌다.**

`YES` 가 나오는 경우는 조원 전원의 목록에 `X` 가 들어 있을 때뿐이다.

## 풀이 아이디어
**핵심 질문: "한 명이라도 안 되면 끝인가, 한 명이라도 되면 끝인가?"**

이 문제는 **전부 만족(AND)** 이다. 그래서 판정을 이렇게 잡는다.

```
ok = True 로 시작한다          ← "일단 된다고 보고"
안 되는 사람을 만나면 False    ← "반례를 찾으면 꺾는다"
한 번 False 가 되면 절대 안 돌아온다
```

방향이 한쪽뿐이라 **조원을 어떤 순서로 보든 결과가 같다.** 이게 이 패턴의 장점이다.

거꾸로 쓰면 틀린다.

```python
for ...:
    if X in A: ok = True       # ✗ 마지막 조원만 반영된다
    else:      ok = False
```

`[4]`, `[1,2,4,5,6,7]`, `[1,3,4]`, `[4,7]` 순서로 들어오면 3번째에서 `True` 로 되살아났다가 4번째에서 다시 `False` — 우연히 답이 맞을 수도 있고 틀릴 수도 있다. **운에 맡기는 코드다.**

반대로 "한 명이라도 되면 YES"(OR) 인 문제라면 `ok = False` 로 시작해서 되는 사람을 만나면 `True` 로 올린다. **시작값과 꺾는 방향이 짝이다.**

## 코드 따라가기

```python
T,X = map(int,input().split())
N = int(input())
```

**① `map(int, ...)` 언패킹 — 개수가 정확히 맞아야 한다**

`split()` 이 만든 조각 수와 왼쪽 변수 수가 같아야 한다.

```python
a, b = "7 3".split()        # a='7', b='3'
a, b = "7 3 9".split()      # ✗ ValueError: too many values to unpack (expected 2)
a, b, c = "7 3".split()     # ✗ ValueError: not enough values to unpack (expected 3, got 2)
```

그래서 입력 형식을 착각하면 **첫 줄에서 바로 죽는다.** `T, N, X` 로 세 개를 받으려 하면:

```
ValueError: not enough values to unpack (expected 3, got 2)
```

`map(int, ...)` 은 조각을 하나씩 `int` 로 바꿔준다. 안 쓰면 `'7' + 1` 같은 데서 `TypeError` 가 난다.

**② `K` 를 읽고 쓰지 않는다 — 그런데 안 읽으면 안 된다** ⚠

```python
K = int(input())                        # 값은 안 쓴다
A = list(map(int,input().split()))
```

`K` 는 코드 어디에도 다시 안 나온다. 그런데 **줄을 먹어치우는 역할**을 한다. 빼면 이렇게 된다.

```python
for _ in range(N):
    A = list(map(int,input().split()))   # ✗ K 줄을 A 로 읽어버린다
```

예제로 추적하면, 1번 조원에서 `A = [1]` (K값 1이 들어온다), 다음 반복에서 `A = [4]` (원래 A였던 것)… 한 칸씩 밀려서 **에러 없이 답만 틀린다.**

값을 안 쓸 거면 `int()` 도 필요 없다. 의도가 더 분명해진다.

```python
input()                      # 줄만 버린다
A = list(map(int, input().split()))
```

**③ `X not in A` — 리스트 멤버십**

```python
if X not in A:
    result = False
```

`in` / `not in` 은 리스트를 처음부터 훑어 있는지 본다.

```python
3 in [1, 3, 4]        # True
3 not in [1, 3, 4]    # False
3 in "134"            # ✗ TypeError — 문자열엔 문자로 찾아야 한다
```

여기서 숫자로 찾을 수 있는 건 `A` 를 `list(map(int, ...))` 로 **숫자 리스트로 만들어뒀기 때문**이다. `int` 변환을 빼고 `A = input().split()` 로 두면 `A` 가 `['1','3','4']` 라서 `3 in A` 가 **False** 가 된다 — 역시 에러 없이 오답이다.

`A` 가 오름차순으로 주어지니 이분 탐색도 가능하지만, `K ≤ 1,000` 이고 `N ≤ 10` 이라 굳이 필요 없다.

**④ `break` 가 없다**

반례를 찾은 뒤에도 남은 조원을 끝까지 돈다. 정답에는 영향이 없다 — `result` 는 한 방향으로만 바뀌니까. `break` 를 넣으려면 남은 입력 줄을 어떻게 소비할지 따로 챙겨야 하는데, `N ≤ 10` 이라 그냥 두는 게 낫다. **최적화가 아니라 취향의 문제다.**

**실행 추적 — 위 예제 (`NO` 케이스)**

`T=7`, `X=3`, `N=4`

| 조원 | `K` | `A` | `3` 있나 | `result` |
|---|---|---|---|---|
| 1 | 1 | `[4]` | ✗ | True → **False** |
| 2 | 6 | `[1,2,4,5,6,7]` | ✗ | False |
| 3 | 3 | `[1,3,4]` | ✓ | False (한번 꺾이면 안 올라온다) |
| 4 | 2 | `[4,7]` | ✗ | False |

→ `NO`

**조원 3에서 `3` 이 있는데도 `result` 가 안 올라가는 게 이 패턴의 핵심이다.**

## 외울 것
> **"전부 만족" 은 `ok = True` 로 시작해 반례에서 `False` 로 꺾는다.** 한 방향으로만 바뀌니 순서에 안 흔들린다.
> ("하나라도 만족" 이면 `False` 로 시작해 `True` 로 올린다 — 시작값과 방향은 짝이다)
> 그리고 **개수 줄(`K`)은 값을 안 써도 반드시 읽어야 한다.** 안 읽으면 입력이 한 칸씩 밀려 **에러 없이 오답**이 된다.
> 에러 없이 조용히 틀리는 3대 함정: **개수 줄 안 먹기 · `int` 변환 빼먹기 · 플래그 방향 뒤집기.**
