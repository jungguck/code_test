## 문제
영문 소문자로만 이루어진 문자열을 정수 하나(해시 값)로 바꾼다. 규칙 세 가지:
1. 각 글자를 숫자로 바꾼다 — `a`=1, `b`=2, …, `z`=26
2. 앞에서 i번째(0부터 센다) 글자의 숫자에 `31^i` 을 곱한다
3. 그것들을 모두 더한 뒤 `1234567891` 로 나눈 나머지를 구한다

`r=31` 과 `M=1234567891` 은 문제가 정해준 값이다. 직접 고르는 게 아니다.

## 입력
- 첫째 줄: 문자열의 길이 `L`
- 둘째 줄: 영문 소문자로만 이루어진 문자열

## 출력
- 계산한 해시 값 하나

## 예제
```
입력       출력
5          4739715
abcde

3          25818
zzz

1          9
i
```
`abcde` 가 왜 4739715 인가:
`1×1 + 2×31 + 3×961 + 4×29791 + 5×923521` = `4739715`.
이 값이 M(1234567891)보다 작아서 **나머지 연산이 아무것도 바꾸지 않는다.** 짧은 문자열에서는 대체로 그렇다.

`zzz` 는 `z`=26 이므로 `26 + 26×31 + 26×961` = `25818`.

## 풀이 아이디어
**핵심 질문: "글자가 몇 번째에 있는지를 어떻게 값에 반영하나?"**

그냥 다 더하면 순서가 사라진다 — `ab` 와 `ba` 가 똑같이 3이 된다. 그래서 **자리마다 다른 계수**를 곱한다. 그 계수가 `31^i` 다.

```
문자열   a     b      c      d       e
숫자     1     2      3      4       5
계수     31⁰   31¹    31²    31³     31⁴
        = 1   = 31   = 961  = 29791 = 923521
곱      1  +  62  +  2883 + 119164 + 4617605  =  4739715
```

여기서 한 가지가 걸린다. **`31^i` 는 i가 커지면 자리수가 폭발한다.** 파이썬 정수는 자리수 제한이 없어서 **에러는 안 나고 느려지기만 한다.** (C++ 이라면 `31^13` 쯤에서 오버플로로 값이 깨진다 — 언어에 따라 증상이 정반대다.)

실제로 재보면 이렇다.

| L | `31 ** i` 방식 | 매 단계 접는 방식 | 결과 일치 |
|---|---|---|---|
| 50 | 0.0000s | 0.0000s | 같음 |
| 1,000 | 0.0027s | 0.0004s | 같음 |
| 5,000 | 0.1615s | 0.0018s | 같음 |
| 10,000 | 0.9661s | 0.0037s | 같음 |
| 20,000 | **6.1715s** | 0.0073s | 같음 |

L이 2배면 시간이 4배씩 뛴다. 이 문제의 L 은 짧아서 `31 ** i` 로도 통과하지만, **습관은 접는 쪽으로 들이는 게 좋다.** 근거는 모듈러 산술의 두 성질이다.

```
(a + b) % M  ==  ((a % M) + (b % M)) % M
(a × b) % M  ==  ((a % M) × (b % M)) % M
```

언제 나눠도 결과가 같으니, **커지기 전에 미리 나눠두면** 된다.

## 코드 따라가기

```python
result += (ord(s[i]) - 96) * (31 ** i)
```

한 줄에 세 가지가 들어 있다. 하나씩 본다.

**① `ord(s[i]) - 96` — 왜 96인가**

`ord()` 는 글자를 아스키 번호로 바꾼다. `'a'` 가 97이라서 96을 빼면 1이 된다.

```python
ord('a')        # 97
ord('a') - 96   # 1   ← 문제가 원하는 a=1
ord('z') - 96   # 26
```

틀린 버전:

```python
ord(s[i]) - 97   # ✗ a=0 이 되어 첫 글자가 통째로 사라진다
ord(s[i]) - 'a'  # ✗ TypeError: unsupported operand type(s) for -: 'int' and 'str'
```

두 번째가 흔하다. `ord()` 는 숫자를 주는데 `'a'` 는 문자라서 뺄 수 없다. 양쪽을 숫자로 맞추려면 `ord(s[i]) - ord('a') + 1` 로 쓴다.

**② `31 ** i` — 거듭제곱**

```python
31 ** 0      # 1
31 ** 3      # 29791
31 ** 1000   # 1490자리 정수 — 에러 없음, 그냥 거대하다
```

`i=0` 일 때 `31 ** 0` 이 1이라, **첫 글자를 따로 처리할 필요가 없다.** 반복문이 그냥 처리한다.

**③ `result % 1234567891` — 마지막에 한 번만**

```python
print(result % 1234567891)
```

`result` 를 다 더한 뒤 마지막에 한 번 나눈다. 짧은 문자열에서는 이것으로 충분하다. 길어질 때를 대비한 형태는 이렇다.

```python
M = 1234567891
result, power = 0, 1
for ch in s:
    result = (result + (ord(ch) - 96) * power) % M
    power = power * 31 % M        # 지수를 키우지 않고, 곱하면서 바로 접는다
```

`31 ** i` 를 매번 새로 만들지 않고 **직전 값에 31을 곱해 이어간다.** 매번 `% M` 을 하니 수가 10자리를 안 넘는다.

**실행 추적 — `abcde`**

| i | 글자 | 숫자 | `31 ** i` | 더하는 값 | 누적 `result` |
|---|---|---|---|---|---|
| 0 | `a` | 1 | 1 | 1 | 1 |
| 1 | `b` | 2 | 31 | 62 | 63 |
| 2 | `c` | 3 | 961 | 2,883 | 2,946 |
| 3 | `d` | 4 | 29,791 | 119,164 | 122,110 |
| 4 | `e` | 5 | 923,521 | 4,617,605 | **4,739,715** |

마지막에 `4739715 % 1234567891` = `4739715`. 나머지 연산이 아무것도 안 바꿨다.

**조용히 틀리는 함정 — 개행 문자**

지금 코드는 `input()` 이라 안전하다. 하지만 길이가 커지는 문제에서 습관적으로 `sys.stdin.readline()` 으로 바꾸면 여기서 터진다.

```python
s = input()                      # ✓ 개행을 이미 떼어준다
s = sys.stdin.readline()         # ✗ 's' 뒤에 '\n' 이 붙어 있다
s = sys.stdin.readline().strip() # ✓
```

`\n` 이 남으면 `ord('\n') - 96` = `10 - 96` = **-86** 이 섞여 들어간다. **에러가 안 나고 답만 틀린다.** 이게 제일 찾기 어렵다.

## 외울 것
> **자리 순서를 값에 넣어야 하면 `sum(숫자[i] × r^i)`.** `ord(글자) - 96` 으로 a=1 을 만든다.
> 거듭제곱은 `r ** i` 로 키우지 말고 **`power = power * r % M` 로 곱하면서 접는다.**
> 파이썬은 큰 수에서 깨지지 않고 **느려질 뿐**이다 — 에러가 없다고 안심하면 안 된다.
> 모듈러 거듭제곱은 아예 내장에 있다: `pow(31, 100000, 1234567891)`.
