# 답지 — G03. 부품 고르기

## 핵심 아이디어
**"모든 조합을 다 만들어본다."** 단, 무식하게 만들지 않고 **가망 없으면 중간에 끊는다.**
이게 백트래킹이다.

N=15면 K개 고르는 경우의 수가 많아야 32,768가지. 다 해봐도 순식간이다.

## 재귀가 어떻게 조합을 만드나
`pick(start, chosen, total)` 은 이렇게 읽는다:
> "start번 부품부터 뒤쪽만 살펴볼 건데, 지금까지 chosen개 골랐고 합은 total이다."

```
pick(0, 0, 0)                     처음: 0번부터 보고, 0개 골랐고, 합 0
 ├ 0번 고름 → pick(1, 1, 5)        다음엔 1번부터 본다
 │   ├ 1번 고름 → pick(2, 2, 11)
 │   │   ├ 2번 고름 → pick(3, 3, 18)  → 3개 다 골랐다! best 후보 18
 │   │   ├ 3번 고름 → pick(4, 3, 19)  → 후보 19
 │   │   └ 4번 고름 → pick(5, 3, 20)  → 후보 20
 │   ├ 2번 고름 → pick(3, 2, 12) ...
 │   └ ...
 ├ 1번 고름 → pick(2, 1, 6) ...
 └ ...
```

**핵심은 `i + 1`** 이다. 다음 재귀에 "그 다음 부품부터 봐라" 라고 넘기기 때문에
같은 부품을 두 번 고르지 않고, `(0번,1번)` 과 `(1번,0번)` 을 중복해서 세지도 않는다.

## 초보가 막히는 곳

**① `return` 이 두 개인 이유**
```python
if total > m:      return    # 실패로 끝 — 여기서 더 가봐야 무게만 늘어난다 (가지치기)
if chosen == k:    return    # 성공으로 끝 — K개를 다 골랐다
```
재귀는 **"언제 멈추는가"** 를 정해주지 않으면 무한히 파고든다. 이 두 줄이 멈추는 조건이다.

**② `global best` 는 왜 필요한가**
함수 안에서 바깥 변수에 **값을 대입하려면** `global` 을 붙여야 한다.
안 붙이면 파이썬이 "함수 안의 새 변수"로 취급해서, 밖의 `best` 는 그대로 -1 이 된다.

**③ 가지치기(pruning)가 진짜 중요한가?**
이 문제 크기에선 없어도 통과한다. 하지만 N이 커지면 이 한 줄이 실행 시간을 수백 배 줄인다.
백트래킹 = 완전탐색 + 가지치기, 라고 기억하면 된다.

**④ 왜 `best = 0` 이 아니라 `-1` 로 시작하나**
0으로 시작하면 "아무것도 못 담았을 때"와 "합이 0일 때"를 구분 못 한다.
무게는 항상 1 이상이니 -1 은 절대 나올 수 없는 값 → 안전한 표시용 값이다.

## 시간복잡도
O(2^N) — N=15면 32,768. 여유롭다. N이 25를 넘어가면 이 방법은 못 쓴다.
