# 답지 — D01. 다음 큰 수

## 핵심 아이디어
**"아직 답을 못 찾은 애들을 스택에 쌓아두고 기다리게 한다."**

새로운 수가 들어올 때마다, 스택에서 기다리던 수들 중 **새 수보다 작은 애들은
답이 바로 지금 정해진다.** 정해진 애들은 스택에서 빼버린다.

## 손으로 따라가기 — `3 5 2 7`

```
i=0, 값 3
  스택 비었음 → 그냥 쌓는다
  stack = [3]                  answer = [-1, -1, -1, -1]

i=1, 값 5
  스택 맨 위 3 < 5  → 3의 답은 5다!  빼내고 기록
  stack = [5]                  answer = [ 5, -1, -1, -1]

i=2, 값 2
  스택 맨 위 5 > 2  → 5는 아직 답을 못 찾음. 그대로 둔다
  stack = [5, 2]               answer = [ 5, -1, -1, -1]

i=3, 값 7
  맨 위 2 < 7 → 2의 답은 7!   stack = [5]
  맨 위 5 < 7 → 5의 답은 7!   stack = []
  stack = [7]                  answer = [ 5,  7,  7, -1]

끝. 스택에 남은 7 은 답을 못 찾았으므로 -1 그대로.
→  5 7 7 -1
```

## 왜 O(N) 인가
`while` 이 안에 있으니 O(N²) 처럼 보인다. 하지만 **각 원소는 스택에 딱 한 번 들어가고,
한 번 빠지면 다시 안 들어온다.** 그래서 `while` 전체가 도는 횟수를 다 합쳐도 최대 N번이다.

> 반복문이 겹쳐 있다고 무조건 O(N²)이 아니다. **"총 몇 번 도는가"** 를 세야 한다.

## 초보가 막히는 곳

**① 왜 값이 아니라 인덱스를 쌓나?**
답을 `answer[어디에]` 적어야 하는지 알아야 하니까. 값만 쌓으면 그 값이 몇 번째 자리였는지 모른다.
```python
stack.append(i)              # 위치를 쌓고
nums[stack[-1]]              # 값이 필요하면 이렇게 꺼내 본다
```

**② `while stack and ...` 의 순서**
```python
while stack and nums[stack[-1]] < nums[i]:
```
`stack` 을 먼저 확인하는 이유는, 스택이 비었을 때 `stack[-1]` 을 하면 **에러**가 나기 때문이다.
파이썬은 `and` 왼쪽이 거짓이면 오른쪽을 아예 안 본다. 이 성질을 이용한 것.

**③ `stack[-1]` 이 맨 위인 이유**
파이썬에서 `-1` 은 **마지막 원소**다. 리스트 끝에 `append` 로 쌓았으니 끝이 곧 스택의 꼭대기.

**④ `print(*answer)`**
`*` 를 붙이면 리스트를 풀어서 하나씩 넘긴다. `print(answer)` 라고 쓰면 `[5, 7, 7, -1]` 처럼
대괄호와 쉼표까지 같이 찍혀서 오답 처리된다.

## 이 유형을 부르는 이름
**모노토닉 스택(monotonic stack)** — 스택 안이 항상 한 방향으로 정렬돼 있다.
"오른쪽에서 처음 나오는 더 큰/작은 값" 류 문제는 전부 이 틀로 풀린다.

## 시간복잡도
O(N)
